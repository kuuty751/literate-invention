# AI 助手 · 使用说明

零构建的大模型应用作业：前端是原生 HTML/CSS/JS（不引第三方框架），后端是一个 FastAPI 服务，
既托管页面也代发请求。**API Key 只存在于服务端 `config.py`，不会下发到浏览器。**

功能：多用户登录/注册/改密码 · 普通对话 · 角色对话 · 联网搜索 · MCP 天气工具调用 ·
**本地知识库问答（RAG）+ 问答缓存（换个问法 0 token 秒回）** · 图片理解 · 文生图 · 图生图 ·
角色提示词在线编辑（实时生效）· 按用户隔离的历史对话。

接口的请求/响应报文全部写在 [function.md](function.md) 里，另可访问 `http://127.0.0.1:8000/docs` 在线试。

---

## 一、架构

```
浏览器 ──http://127.0.0.1:8000──► api.py (FastAPI)
         同域，没有跨域问题           │
                                     ├─ 校验登录态（HttpOnly Cookie）
                                     ├─ 读写 prompts/*.md、history/*.json、users.json
                                     ├─ 拉起 mcp_server.py（天气工具，子进程 stdio）
                                     ├─ rag.py：切片 → 向量化 → kb/*.json 索引 → 余弦检索 → 问答缓存
                                     ├─ vstore.py：通用向量集合层（增删 / 元数据过滤 / LRU），缓存存在它的 qa.json
                                     │
                                     └─ 拼上 Authorization: Bearer <Key> ──► 阿里云百炼
                                              文本 qwen-plus / 视觉 qwen3-vl-plus / 出图 qwen-image-2.0 / 向量 text-embedding-v3
```

- 前端只发送 `{model, baseUrl, messages, temperature, seed, max_tokens, stream, enable_search, mcp, rag, cache}`，不含任何密钥
- `GET /api/health` 供页面探测后端是否在线、Key 是否已填、支持哪些出图模型和尺寸、知识库参数
- `api.py` 把项目根目录挂成静态目录，并用一道中间件拦住 `.py` / `.json` 等文件，
  否则 `http://127.0.0.1:8000/config.py` 会把密钥明文发出去

## 三、首次配置（只需一次）

打开 [config.py](config.py)，把第 9 行 `API_KEY` 的空字符串换成你自己的 Key：

```python
API_KEY = "sk-xxxxxxxxxxxxxxxx"
```

Key 申请入口：

- 阿里云百炼：https://bailian.console.aliyun.com/?apiKey=1
- DeepSeek：https://platform.deepseek.com/api_keys
- 智谱 GLM：https://open.bigmodel.cn/usercenter/apikeys
- OpenAI：https://platform.openai.com/api-keys

其余可改项：`BASE_URL`（上游端点，不带 `/chat/completions`）、`MODEL`、`HOST` / `PORT`、
出图相关 `IMAGE_MODEL` / `IMAGE_SIZES` / `IMAGE_MAX_COUNT`、`ROLE_IDS`（允许写提示词 md 的角色白名单）、
知识库相关 `EMBED_MODEL` / `EMBED_DIM` / `RAG_TOP_K` / `RAG_MIN_SCORE` / `RAG_CHUNK_CHARS`、
问答缓存相关 `CACHE_ENABLED` / `CACHE_MIN_SCORE` / `CACHE_MAX_ENTRIES`（都见第八节）。

**知识库不需要再配第二个 Key**——向量化复用上面这一把，只是换了一个 `/embeddings` 端点。

> `HOST` 保持 `127.0.0.1` 表示只有本机能用；改成 `0.0.0.0` 会让同一局域网其他人也能用上你的 Key。
> **提交作业前把 `API_KEY` 改回 `""`，并且到控制台轮换掉用过的那把。**
> 顺手清理：`history/` 里的测试聊天记录、`kb/` 里的演示索引和 `kb/collections/qa.json` 里的问答缓存、
> `users.json` 里多余的测试账号，都可以直接删掉——
> 这些文件按需创建（`users.json` 删掉后需要先注册一个账号才能登录），删了就是全新状态。

## 四、启动与停止

```bash
cd D:\AIchat
python api.py
```

看到 `AI 助手 -> http://127.0.0.1:8000` 后，浏览器打开 **http://127.0.0.1:8000**。
停止：在该终端按 `Ctrl + C`。

- 改 `config.py` / `api.py` / `auth.py` / `store.py` / `rag.py` / `vstore.py` → **必须重启后端**
- 改 `index.html` / `js/*.js` / `css/style.css` → 浏览器 `Ctrl + F5` 强刷即可
- 改 `prompts/*.md` / `history/*.json` / 重新上传知识库文档 → 什么都不用做，下次请求就读到新内容

> 关掉页面再回来还要重新登录：会话 token 故意只存内存，重启服务即全部失效（不落盘更安全）。

## 五、账号

| 操作 | 位置 | 说明 |
|---|---|---|
| 注册 | 首页「注册」标签 | 用户名 2~32 位（中文/字母/数字/`_`/`-`），密码至少 6 位；注册后自动登录 |
| 登录 | 首页「登录」标签 | 成功后服务端下发 `HttpOnly` Cookie `ai_session`，7 天滑动有效期 |
| 退出 | 侧栏底部头像右边 | 清除会话与 Cookie |
| 修改密码 | 配置 → 参数配置 → 修改密码 | 需要原密码；改完该账号所有已登录设备都要重新登录 |

账号存在项目根目录的 `users.json`，**只有随机盐 + PBKDF2-SHA256（12 万次迭代）摘要，没有明文密码**，
校验用 `hmac.compare_digest` 恒时比较。所以忘记密码只能重新注册，没法"查出来"。
聊天记录和提示词都按用户名分开存，换账号看不到别人的会话。

## 六、界面用法

侧栏三个分组（窄窗口会自动折叠成图标条，点左上角箭头展开；点分组名展开/收起该组）：

| 分组 | 内容 |
|---|---|
| **对话** | 普通对话 + 5 个课程内置角色 + 知识库问答（RAG）+ 图片理解 |
| **图片处理** | 文生图、图生图 |
| **知识库** | 资料管理（上传文档、看已入库列表、检索测试、问答缓存管理） |
| **配置** | 参数配置、老师/医生/周公解梦/婴儿取名 4 个提示词编辑器、知识库提示词、自定义角色 |

### 对话

- **Enter** 发送，**Shift + Enter** 换行（输入框自动长高）
- 生成中「发送」变灰，可点「停止」中断，**已生成的部分会保留**
- 每条回复下方：**复制**、**重新生成**（只有最后一条有）
- 顶部「新会话 / 清空」清空的是**当前角色**的记录（会弹确认框）；一个角色始终只有一条记录
- 状态灯显示当前模型名；后端掉线/没填 Key/未登录时会直接写明

输入框左边三个开关：

- **知识库问答** — 勾上后每轮提问先在本机知识库里检索，把最相关的几段拼到系统提示词里，见第八节。
  选中左侧「知识库问答（RAG）」角色会自动勾上它。勾了它，**或者用温度锁在 0 的角色**，都自带**问答缓存**：
  换个问法问过、且相似度够高，直接复用上次的答案、不再调模型（气泡上会出现「缓存命中 0.86 · 0 token」的绿标），
  同样见第八节
- **联网搜索** — 给请求加 `enable_search`，回答前先检索，耗时略长（百炼 compatible-mode 原生支持）。
  勾了知识库或 MCP 时这个开关不生效，避免三个来源混在一起
- **MCP 天气** — 勾上后由模型自己判断要不要调用天气工具，见下一节。这一路是多轮调用，
  **会自动改成非流式**（没有打字机效果），回复下方会标出实际调用了哪个工具、查的哪个城市

### 内置角色

| 角色 | 温度 | 风格 |
|---|---|---|
| 普通对话 | 跟配置页（默认 0） | 无预设，直接问 |
| 大模型应用开发老师 | 锁 0 | 选择题给「答案 + 依据 + 逐项排除」，简答按【结论】【要点】【易错】三段 |
| 医生 | 锁 0 | 健康科普，按【可能原因】【需要观察】【在家缓解】【必须尽快就医】四段，结尾固定一句就医提醒 |
| 周公解梦 | 0.8 | 【梦境意象】【传统寓意】【心理视角】【今日建议】，标注属民俗文化 |
| 婴儿取名 | 0.9 | 一次给 6 个名字的四列表格（名字｜拼音｜出处｜寓意），每次换一批 |
| 爱莉希雅 | 0.9 | 角色扮演，2~4 句、每句结尾带 ♪，知识性问题照样给正确答案 |
| 知识库问答（RAG） | 锁 0 | 只按检索到的资料回答，按【结论】【依据】【出处】三段，引用处标「据[资料2]」 |

### 同一道题不要每次给不同答案

答题类角色的提示词按「锁死输出契约」写：先给结论、再给依据、逐项排除，字数和条数都定死，
数字和阈值只准照抄资料原文，题干缺条件时统一回「题干信息不足：缺＜…＞」。
**同一个人在同一道题上反复问，选哪个、形状、算式是同一份**，不会出现「这次讲三种解法、下次只讲一种」那种漂移。

一共建了四层，各管一段——前三层管「不会选错、形状不变」，第四层才管「字面一模一样」：

1. **温度 `temperature` 默认 0**（贪心采样）。本机实测：同一道选择题温度 0.7 时三次三种写法，
   0.2 即使带固定 seed 还在漂；温度 0 时「选哪个」从来不漂，但长答案的措辞每次仍可能有出入
2. **固定 `seed`（默认 20261104）**下发给上游。配置页能改，改成别的数字就是另一批结果
3. **输出契约**（上面那段提示词）把能漂的空间压到最小。压掉了形状，也压掉了这类跑偏：
   契约原先写「答案：X ｜ 选项原文」，模型有几次把「选项原文」四个字照抄进答案，
   现在改成「竖线后面必须是题干里那串字，不许写「选项原文」这四个字」，之后 6 次现生成每次都老老实实抄成「5和12」
4. **问答缓存**把「逐字一致」这件事变成 0 成本：温度 0 的角色每轮回答都存进 `kb/collections/qa.json`，
   下次同义改写也命中，回放第一次那段话——**连标点都不变**（见第八节）

**为什么非要有第 4 层**：百炼在服务侧并不保证跨请求逐字复现。实测关掉缓存连问三次
（温度 0 + seed 都不变，`cache:false`），三份文本两两不同——算式有时写成 `2+3=5` 有时写成 `2 + 3 = 5`，
三条排除理由每次重排用词——**但「答案：B ｜ 5和12」和这两个数值三次都没变**。
所以「不会选错」靠 1~3 层，「一个字都不差」靠第 4 层。

实测（`qwen-plus`，同一道笛卡尔积选择题）：

| 怎么问 | 耗时 | token | 结果 |
|---|---|---|---|
| 课程老师 + 关检索，第一次（现生成） | 5.12 秒 | 780 | 答案：B ｜ 5和12，再走依据 + A/C/D 不选 |
| 同一句话第二次（缓存回放） | **0.44 秒**（连测 5 次 0.41~0.46） | **0** | 与第一次**逐字节相同**，徽标「缓存命中 1.00 · 0 token」 |
| 关掉缓存连问三次（温度 0 + seed） | 4.68 / 4.71 / 4.42 秒 | 780 / 781 / 770 | 三份文本两两不同（措辞、算式空格在漂）；**选项 B 和 5、12 这两个数值三次都没变** |
| 同一句话但勾上「知识库问答」 | 4.86 秒 | 约 2000 | **不回放**上面那条：作用域含「开没开检索」，带引用的答案不会串给纯问答 |
| 婴儿取名（温度 0.9）连问两次 | 13.5 / 15.7 秒 | 两次都调模型 | 两次名字和出处**都不一样**，也不进缓存 —— 创意角色要的就是变化 |

作用域键是 `sha1(模型 + 所有 system 文本 + 模式 + 温度)`，同一道人设下实测四个键互不相同：
检索关 t=0 是 `1dbd901c70b2c9fa`，检索开 t=0 是 `f2ec783a8e4d5a97`，
检索关 t=0.7 是 `1ff71f7c51e2f9b2`，检索关 t=0.2 是 `c17174c598f76403`。
温度一改键就变，所以把温度调上去想要「换个说法」时，不会先被旧答案拦住。

## 七、MCP 天气查询

项目自带一个本地 MCP 服务，不依赖任何付费 Key：

```
勾上「MCP 天气」→ api.py 用 stdio 拉起 mcp_server.py 子进程
  → tools/list 拿到 get_weather 的参数表 → 塞进对话请求的 tools 字段
  → 模型回 tool_calls → 本地执行（查 Open-Meteo 免费天气接口）
  → 结果以 role=tool 回填 → 再问一次 → 得到带真实数据的回答
```

- 手动验证工具本身：`python mcp_server.py --check 杭州 3`
- 模型判断不需要查的问题（比如"写首诗"）就不会调工具，`mcpCalls` 返回空数组
- 最多 4 轮工具调用，超出会中止；子进程用完即回收，不占端口
- 想换成阿里云百炼托管的高德 MCP：端点是
  `https://dashscope.aliyuncs.com/api/v1/mcps/amap-maps/mcp`，鉴权复用 `config.py` 里同一个 Key，
  但**必须先在控制台点「立即开通」**（https://bailian.console.aliyun.com/#/mcp-market），
  没开通直接调会返回 `未开通该MCP或非可用开通状态`

## 八、知识库问答（RAG）

四步：**入库**（切片 → 向量化 → 存本地 JSON）→ **检索**（问题也向量化，算余弦相似度取前 K 段）→
**注入**（拼到系统提示词后面）→ **生成**（让模型只按资料回答并标 `[资料n]`）。
生成完还有一步：**这轮问答进缓存**，下次换个问法再问就直接复用，不再调模型（见下面「问答缓存」）。

### 怎么用

1. 侧栏 **知识库 → 资料管理**，把 `.md` / `.markdown` / `.txt` 拖进虚线框（或点击选文件），可以一次选多个；
   单份正文上限 80000 字，前端还限制了单个文件 800 KB
2. 等它切片 + 向量化（状态栏会显示耗时），完成后「已入库文档」列出文件名、字数、片段数、入库时间
3. 下面的**检索测试**输入一个问题，只看命中了哪几段、相似度多少——**这一步不调大模型、不花 token**，专门用来调阈值
4. 回对话页选 **知识库问答（RAG）** 角色（会自动勾上输入框旁的「知识库问答」开关）提问。
   回答里带「据[资料2]」这样的编号，气泡右上角显示「知识库 4 段」，鼠标悬停能看文件名和相似度
5. 同一页往下滚就是**问答缓存**卡片：存了几条、累计复用几次、当前阈值、文件多大，
   还能输入一句话**只探测不调模型**，以及单条删除 / 一键清空

库里已经存了一份本 README 作为演示资料（片段数随文档长度变，「已入库文档」那一栏直接显示）。演示时有两条现成的路线，
下面这几个数都是本机跑出来的：
- **问答缓存**：先用「知识库问答（RAG）」角色问「文档片段的检索相似度门槛默认是多少？」，
  3~4 秒、约 1900 token，答案是 **0.45**（`RAG_MIN_SCORE`，别和缓存的 0.80 弄混）；
  再换个说法问「知识库检索的相似度阈值默认是多少？」——**0.5 秒**蹦出来、`usage` 全 0，
  气泡上挂着「缓存命中 0.86 · 0 token」的绿标，复用的是上一句那个 0.45 的答案
- **同题同答**：切到「课程老师」（不用勾知识库）问那道笛卡尔积的单选题，第一次 5.12 秒、780 token，
  第二次同样的话 **0.44 秒、0 token，文本和第一次逐字节相同**；把温度从 0 改成 0.7 再问，
  作用域键从 `1dbd901c70b2c9fa` 变成 `1ff71f7c51e2f9b2`，不会被旧答案拦住

### 参数（`config.py`，改完要重启后端）

| 参数 | 默认 | 作用 |
|---|---|---|
| `EMBED_MODEL` | `text-embedding-v3` | 向量化模型，**只有百炼兼容端点上有**；换 DeepSeek/智谱/OpenAI 预设时知识库会报错，对话不受影响 |
| `EMBED_DIM` | `1024` | 维度，可选 512 / 768 / 1024 |
| `RAG_CHUNK_CHARS` | `500` | 每片目标字数 |
| `RAG_CHUNK_OVERLAP` | `80` | 相邻片段的重叠字数，防止一句话被拦腰截断 |
| `RAG_TOP_K` | `4` | 一次注入几段 |
| `RAG_MIN_SCORE` | `0.45` | **文档片段**的门槛：检索出来的片段相似度低于 0.45 就不拼进上下文（和下面 0.80 是两个不同的东西，别看混） |
| `RAG_MAX_DOC_CHARS` | `80000` | 单份文档正文上限 |
| `RAG_MAX_CHUNKS` | `200` | 单份文档切片上限 |
| `RAG_CONTEXT_HEAD` / `TAIL` | 见文件 | 注入资料时前后的说明文字，直接改这两段就能调整"必须标注编号""资料不足时说明缺哪部分"这些要求 |
| `CACHE_ENABLED` | `True` | 问答缓存总开关，关掉每次都要重新生成 |
| `CACHE_MIN_SCORE` | `0.80` | **两个问题之间**的门槛：相似度高于 0.80 才算"问的是同一件事"、才复用旧答案（来历见下面「问答缓存」；它不是文档片段的门槛，那个是上面的 0.45） |
| `CACHE_MAX_ENTRIES` | `200` | 缓存条数上限，超了淘汰最久没被命中的 |
| `CACHE_TTL_SECONDS` | `0` | 多少秒没再问到就过期，`0` = 不按时间过期 |
| `CACHE_COLLECTION` | `qa` | 缓存集合名，对应 `kb/collections/qa.json` |

切片做法：先按 Markdown 标题切大段，每段再按句子装箱到 500 字左右，续接的块会重新冠上所属标题，
避免第 2 片看不出自己在讲哪一节。

**调参实测**：早前用本课程三份文档测的时候，真正相关的片段相似度在 **0.49~0.74**，
而「今天晚饭吃什么」这种无关问题最高只有 **0.41** —— 所以阈值卡在 0.45，无关问题直接 0 命中、不往提示词里塞垃圾。
**换成现在这份 README 入库，同样的探测要松一些**：问「文档片段的检索相似度门槛默认是多少？」命中 4 段，
最高 0.8 上下、最低 0.67；问「今天晚饭吃什么」只有一段勉强过 0.50、另一段 0.48，
拼进去的就是参数表那两段（报文见 function.md 8.4）。想更干净就把 `RAG_MIN_SCORE` 调到 0.50~0.55，代价是同义改写也更容易被挡。
检索测试页会标出各候选的相似度，过了阈值但只有 0.45~0.50 的显示成灰色卡片（相关但不强）；
一段都没过时告诉你候选段数和当前阈值，据此决定是降阈值还是改文档。

另一个坑：`embeddings` 接口**一批最多 10 条**，传 11 条上游直接 `HTTP 400`。后端按 10 条一批循环调用，
所以入库耗时 ≈ 片数 ÷ 10 次网络往返：239 字 3 片用 0.5 秒，7600 字 25 片用 22 秒。

### 存储与安全

- **一份文档一个 `kb/<文档 id>.json`**：切片原文 + 1024 个浮点数（四舍五入到 5 位小数控制体积，约 10 KB/片）。
  纯 Python 写 JSON，**没有向量数据库、没有新增任何第三方依赖**，和 `history/*.json` 一样是"本地文件持久化"这个知识点
- **问答缓存一个 `kb/collections/qa.json`**：存的是「问题向量 + 完整答案 + 引用 + 作用域 + 参数指纹」，一条约 10 KB
- 文档 id 由后端生成（`d` + 时间戳 + 随机 4 位），**显示名不参与路径拼接**，所以文件名传 `../../x` 也写不到项目外面；
  集合名要过 `^[a-z][a-z0-9_]{1,30}$`、条目 id 要过 `^[A-Za-z0-9_-]{1,48}$`，同理
- 写入是 `.tmp` + `os.replace` 原子替换，外面一把进程锁串行化
- `kb/*.json`、`kb/collections/*.json` 和 `.py` 源码一样被静态目录拦截：浏览器直接访问
  `http://127.0.0.1:8000/kb/collections/qa.json` 是 **404**，只能走 `/api/rag/*` 接口
- 改了 `EMBED_MODEL` 或 `EMBED_DIM` 后，旧文件的向量和新模型不可比，检索会**自动跳过**它们（`diag.skipped` 能看见跳了几片），
  页面上标成「模型已变更，需重新上传」，删掉重传一次即可

### 问答缓存：换个问法也秒回

**两种情况自动生效，没有第二个开关**：勾了「知识库问答」，或者用的是温度锁在 0 的角色
（课程老师 / 医生 / 知识库问答，以及默认温度下的普通对话）。每次回答完，这一轮的「问题向量 + 答案 + 引用了哪几段」
会写进 `kb/collections/qa.json`；下次提问时，先把这句话向量化**一次**，拿它去缓存里找最像的旧问题，
够像就直接把存好的答案发回去——**一次大模型都不调、0 token**。不够像才照常检索 + 生成，然后把新的这轮存进去。
温度调上去（>0）的角色不查也不写：把温度调高本来就是想要变化，不该再拿旧答案拦它。

实测（本机今天取的，作用域都是「知识库问答（RAG）」角色 + 开检索 + 温度 0；
「探测」接口只做向量化和比相似度、不调模型，所以下面这些分数是可以重复验证的）：

| 这一问（库里已有第一行那句） | 相似度 | 结果 |
|---|---|---|
| 文档片段的检索相似度门槛默认是多少？（首次真正提问） | — | 3.48 秒、1950 token，答 **0.45** |
| 文档片段检索的相似度门槛默认是多少？ | 0.9971 | 命中，回放上面那段 |
| 文档片段的检索相似度门槛默认值是多少？ | 0.9959 | 命中 |
| 知识库检索的相似度阈值默认是多少？ | 0.8613 | 命中（「文档片段→知识库」「门槛→阈值」都换了词） |
| 片段检索的门槛默认值是多少来着 | 0.8409 | 命中，压线过 |
| 那这道笛卡尔积的题选什么 | 0.4137 | **不**命中，跨话题不串味 |

命中之后真正提问的耗时是 0.41~0.46 秒（连测 5 次），`usage` 三个数全 0。
气泡时间行上会出现绿色徽标「缓存命中 0.86 · 0 token」，鼠标悬停能看到它复用的是哪句旧问题；
引用清单 `X-RAG-Sources` 照样回放，所以「据[资料2]」的编号不会丢。刷新页面徽标还在（写进历史 meta）。

**阈值 0.80 是量出来的，不是拍的。** 本机把同一话题的各种问法两两算余弦：

- 同一意思的不同问法：上面那张表就是证据，**0.8409 ~ 0.9971** 都落在 0.80 以上；
  更早一轮还测过 `切片大概多少字一片 ↔ 切片多少字一片` **0.9174**、`检索阈值默认值是多少来着 ↔ 默认阈值是多少` **0.8824**
- 不同意思的问题之间：今天测的是 **0.4137**（笛卡尔积那道题 ↔ 阈值这个问题），更早一轮跨话题最高也只有 **0.5658**

所以 0.80 落在「字面接近的改写能命中、跨话题绝不串味」的区间。原来定的是 0.92，结果同义改写几乎全漏，
降到 0.80 才符合直觉。**缓存的取舍是宁可漏命中也不要答错**：漏命中只是慢 3 秒，答错会被一直复用。

不会命中的几种情况（都是实测）：
- **换了人设、模型、检索开关或温度**：缓存按「system 提示词 + 模型 + 模式（开没开检索 / 开没开联网搜索）+ 温度」
  的 sha1 前 16 位分成不同作用域，改任何一样都不会串用——勾知识库的答案带「据[资料2]」，
  没勾的不能拿它回放。列表里会看到两条同样的问题、`作用域` 不同
- **改了检索参数**：每条缓存记着写入时的 `向量模型|维度|topK|阈值|切片字数`，改了 `RAG_MIN_SCORE` 这类参数后旧条目标灰、不再复用
- **文档被删或同名重传**：引用过那些文档的缓存条目连带删除（`/api/rag/doc/remove` 会回 `cacheDropped` 条数）
- **没资格被复用的回答**：空答案、勾了 MCP 的请求（有实时数据）、图片理解那种多模态请求、中途点「停止」打断的半截流式回答，都不写入
- **首次就答歪**：缓存会忠实复用歪答案。这个项目就发生过一次——README 旧版有句话写得像「默认阈值 0.42」，
  模型照着答了 0.42，换个问法又秒回了一遍 0.42。改完文档要**重新入库**（同名覆盖会自动让旧缓存失效），别只清缓存

管理入口在 **知识库 → 问答缓存**：显示条数、累计复用次数、当前阈值、文件体积，以及当前是按哪两种情况生效；
「探测」输入一句话**只查缓存、不调模型**，命中与否都会告诉你库里最像的那条有几分、离阈值差多少，
末尾还会写明这次探测用的作用域（人设 + 检索开关 + 温度）；支持单条删除和一键清空。

### 底层那层向量集合能力（`vstore.py`）

问答缓存不是硬写在 `rag.py` 里的，它踩在一个通用的**向量集合（collection）**层上，形状照着向量数据库的
collection 设计，实现是纯 Python + JSON 落盘，没有新增任何依赖：

| 能力 | 对应函数 | 说明 |
|---|---|---|
| 集合隔离 | `kb/collections/<name>.json` | 名字要过 `^[a-z][a-z0-9_]{1,30}$`，所以拼不出项目外的路径 |
| 增量写入 | `upsert(name, items)` | 按 id 覆盖，只写变化的那几条，不重建整份集合 |
| 元数据过滤 | `query(..., where={"scope": ...})` | 列表值按「包含」匹配，缓存用它做作用域隔离、按文档失效 |
| 删除 | `delete(name, ids=…)` / `delete(name, where=…)` | 按 id 删，或按元数据批量删 |
| 命中计数 + LRU | `bump_hits(name, id)` | 命中就 `hits+1` 并推 `updatedAt`；超过 `CACHE_MAX_ENTRIES` 淘汰最久没被命中的 |
| 统计 | `stats(name)` | 条数、模型、维度、体积、累计命中数，页面上那些数字就是它 |

文档索引（`kb/<文档 id>.json`）还是原来那份「一文档一文件」的实现，没有为了这个改造它；
集合层是新增的，问答缓存是它的第一个使用者——要再加「同一份资料的历史提问排行」之类的东西，直接建新集合就行。

### 怎么证明"是检索在起作用，不是模型瞎编"

往文档里塞一句**只有这份文档才有**的编号（比如 `AICHAT-2026-1147`），然后问"我的提交编号是多少"：

| 请求 | 结果 |
|---|---|
| 带 `"rag": true` | 答对 `AICHAT-2026-1147`，并标注「据[资料1]」 |
| 不带 `rag` 字段 | 「我无法获取或查询您的提交编号…」，响应头里也没有 `X-RAG-Sources` |

这组对照是答辩时最好演示的一条——编号不在模型的常识里，只能从文件里检索出来。
真实报文（含响应头）见 [function.md](function.md)：检索注入在 5.5，缓存命中在 5.6，
知识库与缓存接口在 8.1~8.7。

### 极简版接受的取舍

- 全库暴力扫描算余弦：几千片以内完全够用，文档上十万片再考虑 FAISS 或百炼知识库
- **文档索引没有增量更新**：改了正文要重新上传（同名覆盖 = 删旧建新，一次做完，顺带让引用旧文档的缓存失效）；
  缓存那一层是增量的（`upsert` 按 id 覆盖、命中只改一条的计数）
- 缓存只认「字面接近的改写」：0.80 的阈值下面大改措辞的问题不会命中，会老老实实重新检索 + 生成
- 只吃纯文本：PDF / Word / 图片要先自己另存成 `.txt` / `.md`
- 文本编码先按 UTF-8 严格解码，失败自动回退 GBK（记事本另存的中文课件能直接入库）

单条内容截到 20000 字，每个角色最多留最近 400 条。

## 十二、配置页

| 字段 | 作用 |
|---|---|
| 服务地址 baseUrl | 上游端点，不带 `/chat/completions` |
| 模型 model | 对话使用的模型名 |
| 温度 temperature | 0~2，越大越发散。**默认 0**（贪心采样），为的是同一道题每次给同一个结论 |
| 随机种子 seed | 默认 `20261104`，温度 0 时它是保险；逐字一致由问答缓存兜底，不是靠它；填 0 表示不下发这个字段 |
| 最大 token | 0 表示不限制 |
| 历史轮数 | 每次带多少轮上下文，0 表示全部带上 |
| 流式输出 | 开着是打字机效果，关掉等全文一次性返回 |

- 这里改的温度**只对没锁温度的角色生效**：`js/config.js` 里 `AI_ROLES` 每项可以带一个 `temp` 字段覆盖它
  （课程老师 / 医生 / 知识库问答锁 0，周公解梦 0.8，婴儿取名 / 爱莉希雅 0.9），
  所以把上面的温度调到 1 也不会让答题角色重新开始漂移
- 温度和 seed 都会进问答缓存的作用域键，改完再问同一个问题不会撞上旧答案

- **保存配置** — 写浏览器本地，优先级高于 `js/config.js`（换浏览器要重新设）
- **测试连接** — 发一条极短请求验证 Key 和地址是否通
- **恢复 config.js 默认** — 清掉浏览器本地那份
- **快捷切换服务商** — 点一下自动填好对应的 baseUrl 和模型（百炼 / DeepSeek / 智谱 / OpenAI 四个预设）
- **自定义角色** — 填名称 + 系统提示词，出现在左侧「对话」分组；删掉时连它的历史一起删

> 页面上**没有 API Key 输入框**，只显示状态（末 4 位，登录后才可见）。换 Key 就编辑 `config.py` 再重启后端。

## 十三、常见问题

**页面显示「后端未启动」**
`python api.py` 没跑，或者端口被别的进程占着。先确认只有一个实例在跑：
`netstat -ano | findstr :8000`，有残留就把那个 PID `taskkill /PID <pid> /F` 掉再启动。
（我这边就遇到过旧进程占着 8000、页面拿到的还是老代码的情况。）

**状态灯显示「Key 未配置」**
`config.py` 的 `API_KEY` 还是空的，或填完没重启后端。

**端口 8000 被占用 / WinError 10013**
改 `config.py` 里的 `PORT`。注意 Windows 保留了若干端口段（如 8044–8143、9055–9154），
落在里面的端口会直接报 `WinError 10013`，换一个即可。

**双击 index.html 打开却不能用**
必须通过 `http://127.0.0.1:8000` 访问。`file://` 打开时请求打不到后端接口，页面会提示。

**刚重启完就要我重新登录**
正常。会话 token 只在内存里，重启即失效（故意的，见第五节）。

**勾了「MCP 天气」回复变成一整块蹦出来、没有打字机效果**
正常。工具是多轮调用，这一路强制非流式。

**MCP 报 "MCP 工具调用失败" 或开关不见了**
`pip install mcp` 装依赖后重启后端；先用 `python mcp_server.py --check 杭州` 单独确认天气源能通。

**知识库问答没检索到东西 / 回答还是靠常识**
先看侧栏「知识库 → 资料管理」：列表为空就是还没上传；再用下面的「检索测试」输入同一个问题，
如果 `hits` 是空的，说明最高相似度没过 `RAG_MIN_SCORE`（默认 0.45，唯一的默认阈值就是它）。
差得不多（最高分 0.43、0.44 这种）把阈值调低到 0.40 再试；差得多就该改文档，把那段内容写得离问题更近一些。
**开关也要确认勾上了**——选中「知识库问答（RAG）」角色会自动勾。

**上传文档报 HTTP 400**
四种情况：正文空、超过 80000 字、切片超过 200 片、文档名为空。报错信息是中文的，直接照着改。

**入库特别慢**
`embeddings` 一批最多 10 条，耗时 ≈ 片数 ÷ 10 次网络往返，7600 字实测 22 秒。想快就调大 `RAG_CHUNK_CHARS`
（片数变少）或者只上传真正相关的章节。

**换了 `EMBED_MODEL` / `EMBED_DIM` 之后问答没反应**
旧索引的向量和新模型不可比，检索会跳过它们（`/api/rag/status` 的 `outdated` 里能看到，页面显示「模型已变更，需重新上传」）。
删掉那几份重新上传即可，对话功能本身不受影响。

**用了 DeepSeek / 智谱 / OpenAI 预设后知识库报错**
正常——`text-embedding-v3` 只在百炼兼容端点上有。把 `BASE_URL` 换回百炼再上传；或者接受只用对话功能。

**第二次问同样的话没有秒回、也没有「缓存命中」徽标**
按顺序排查：① 这个角色的温度不是 0、也没勾「知识库问答」→ 本来就不查缓存（想要变化才调温度）；
② 换了角色的 system 提示词、换了模型、勾/没勾知识库、或者改了温度 → 作用域不同，本来就不该复用；
③ 改过 `RAG_MIN_SCORE` / `RAG_TOP_K` / `RAG_CHUNK_CHARS` / `EMBED_MODEL` → 参数指纹变了，旧条目标灰；
④ 那次勾了 MCP、是图片理解、或中途点了「停止」→ 这种答案没资格进缓存；
⑤ 相似度没到 `CACHE_MIN_SCORE`。
到底卡在哪一条，用「知识库 → 问答缓存 → 探测」输入那句话，它会告诉你库里最像的一条有几分、差多少，末尾还会写明这次用的作用域。

**明明命中了缓存，这一次还是要十来秒**
命中路径也要先把这句话向量化（唯一的一次上游往返），而 `embeddings` 接口偶尔很慢——本机十几次向量化里
有两次是 10 秒上下，其余都在 0.4~0.5 秒。判断到底命中没有，看响应头 `X-RAG-Cache` 和 `usage` 是不是三个 0，
别看耗时。

**换个问法只有 0.79，差一点就命不中**
会重新生成，并作为**第二条**存进缓存（同一个意思存了两条是正常的，各复用各的）。
想更宽松就调低 `CACHE_MIN_SCORE`，但实测不同话题的问题之间最高只有 0.57，
降到 0.70 以下就有串答案的风险——**缓存答错比没缓存更糟**。

**缓存一直秒回一个错答案**
说明首次那次就答歪了（常见于文档措辞让模型误会）。改文档内容 → 同名重新上传一次，
引用过旧版本的缓存会自动失效；或者在缓存卡片上直接删掉那条 / 清空。
只清缓存不改文档不行，重新生成一次还是歪的。

**问答缓存会不会把我聊过的全都存下来**
不会。只有**温度为 0 的角色或勾了知识库**的纯文本回答才写缓存（MCP、图片理解、空答案、中途停止都不写），
存的是一句问题 + 一段答案 + 引用编号，落在 `kb/collections/qa.json` 一个文件里；
这个文件不走 URL 访问（直接请求是 404），也不含任何密钥。最多 200 条，超了淘汰最久没被命中的。
不想让它存：把配置页温度改成大于 0，且别勾知识库，就一条都不会进（缓存卡片上也能一键清空）。

**改了 JS/CSS 没效果**
`Ctrl + F5` 强刷。后端已经给所有静态资源带了 `Cache-Control: no-cache`，内容没变时走 304 不费流量；
加这个头之前，浏览器会按启发式把 `js/config.js` 缓存住，改完默认值刷新还是旧文件。
`js/config.js` 里的新默认值还可能被浏览器本地存过的旧配置盖掉（**参数配置**里的值优先级更高），
所以加载时会做一次一次性迁移：本地那份没有 `seed` 键就当成老配置，采样参数按 `config.js` 重来。

**图片理解答非所问、每次答案都不一样**
十有八九是把 `visionModel` 设成了纯文本模型，改回 `qwen3-vl-plus`。

**换模型报 404 Model not exist**
该模型名在你的账号/端点上不可用。不同账号可开通的模型不同，
例如 `qwen-vl-plus`、`qwen-vl-max` 在部分账号上是 404 或 403。

**出图报 500 / 没有返回图片**
多为模型名或尺寸不在账号可用范围；先按 `GET /api/health` 里给的 `imageModels`、`imageSizes` 选。
